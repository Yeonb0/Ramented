## Must preserve

- 요구 : **R5** 다녀온 메뉴를 기록, **R8** 운영자 혼자 다 채우지 않음 (방문자 태깅으로 속성이 바뀜)
- **B8** : 보기는 로그인 없이, 기록 · 태깅은 로그인 필수
- **B4** : 시드 값은 표를 세지 않는 초기값. 태깅이 확정되면 근거가 "방문자 n명"으로 바뀐다
- **B5 · B9 해산물 규칙** (응답 중 "모르겠음"은 세지 않음) :
  - 포함 확정 : 포함 ≥ 2 이고 포함 > 미포함
  - 미포함 확정 : 미포함 ≥ 2 이고 포함 0
  - 변경 의심 : 미포함 확정이 된 뒤 포함 ≥ 1 → 필터에서 탈락. 마지막 포함 이후 미포함 ≥ 2이면 미포함 확정으로 돌아감
  - 의견 갈림 : 응답은 있으나 위 어느 것도 아님
  - 응답이 없으면 시드 값 (포함) 또는 모름
- **국물 규칙** : 한 값의 응답 ≥ 2 이고 다른 값보다 많으면 확정, ≥ 2인 값이 동률이면 의견 갈림, 그 밖은 시드 값 또는 모름
- **B6 · B7** : 별점은 회원마다 가장 최근 기록 하나로 평균, 인원수 항상 표시. 기록은 모두 남아 내 기록에 보인다
- **B10** : 오래된 값을 지우지 않고 "마지막 확인 : n개월 전 · n명"
- 로그인 없이 기록하기 · 제보하기를 누르면 하려던 동작을 저장했다가 로그인 후 그 화면으로 이어간다 (N8 · S9 · N9)

## 트랙별 작업

### 🎨 디자인

- 로그인 / 가입, 기록 작성 (별점 · 방문일 · 태깅 · 근거), 내 기록 목록 · 빈 상태, 프로필

### ⚙️ 백엔드

1. `docs/api-contract-v2.md` 에 인증 · 기록 저장 · 내 기록을 먼저 적고 확인받는다
2. Spring Security + JWT, 회원 테이블
3. 기록 · 태깅 저장 (N10) + 검증
4. N2 확정 규칙 + **규칙 표 전체를 덮는 단위 테스트** (각 상태로 들어가고 나오는 경우, 변경 의심과 그 해제)
5. N5 회원별 최근 별점
6. 필터 판정 (N3) 이 새 상태를 그대로 쓰는지 확인

### 📱 프론트

1. 토큰 저장 (기기 보안 저장소), 로그인 확인과 "로그인 후 이어가기"
2. 기록 작성 화면, 저장 후 메뉴 상세가 다시 조회되어 갱신
3. 내 기록 탭, 프로필 탭

## Execution appetite (제안 — 관리자님 수락 필요)

- Protect : 해산물 안전 규칙 (B5 · B9) 과 그 테스트, 로그인 후 이어가기, 저장 실패 시 입력 유지
- Cut first : 프로필 탭의 꾸밈, 내 기록의 정렬 옵션
- Stop when : 완료 기준 충족 또는 기획으로 돌아갈 때
- 다음 Phase (지인 베타) 가 이 Phase에 기다리고 있으니, 범위를 늘리지 않는다

## Execution contract

- Goal condition : 계정 두 개가 같은 메뉴에 "안 들어있음"을 태깅하면 메뉴 상세에 "미포함 · 방문자 2명 · 마지막 확인 오늘"이 보이고, 해산물 제외 필터에서 그 가게가 "통과 1개"로 나타난다 (T8, T2b). 이어서 세 번째 계정이 "들어있음"을 태깅하면 "변경 의심"이 되고 필터에서 빠진다 (T9)
- Required checks : N2 규칙 단위 테스트, 인증 · 기록 API 테스트, 앱에서 T6 ~ T9 · T14 ~ T16 확인
- 바꿔도 되는 곳 : `backend/`, `app/`, `docs/api-contract-v2.md`, `docs/planning/phases/`
- 바꾸지 않을 것 : 기획 문서, 제보 (Phase 6), 배포 설정 (Phase 5)
- 기획으로 돌아갈 때 : 가입 방식 (아래 Open questions) 이 정해지지 않았다, 규칙 표로 결정되지 않는 경우가 나온다, 기록 수정 · 삭제가 필요해진다
- Checkpoint : 인증 / 기록 저장 + 규칙 / 기록 화면 / 내 기록 · 프로필 단위로 PR
