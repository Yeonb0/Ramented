## Task

- 이번 Phase : 회원이 오늘 휴무 · 오늘 영업 · 이벤트를 제보하고, 영업 상태와 이벤트 한 줄이 가게 상세에 반영된다. 인스타 · 카카오맵으로 나가는 링크를 붙인다
- breadboard 흐름 : **T10, T11, T12, T13**

## Do not use as build scope

- 이벤트 상세 (사진 · 기간 · 조건 등 구조화된 정보), 인스타 게시물 앱 내 표시 (D4), 사장님 참여 — 모두 v2.0 cut
- 제보 신고 · 삭제 기능

## Must preserve

- 요구 : **R2** 인스타를 쓰지 않아도 휴무 · 이벤트를 알 수 있다, **R3** 불확실하면 확실한 척하지 않는다
- 제보는 로그인 필수 (B8). 로그인 없이 누르면 Phase 4의 "로그인 후 이어가기"를 그대로 쓴다
- 유효 기간 : 휴무 · 영업 제보 **24시간**, 이벤트 **기본 7일** (제보자가 줄일 수 있음)
- 영업 상태 우선순위 (N4) : 유효 제보 → 같은 날 영업 / 휴무가 엇갈리면 "제보 엇갈림 — 인스타 확인" → 제보 없으면 정기 영업시간 → 그것도 없으면 모름
- 근거 문구에 제보 근거와 시각을 넣는다 (예 : "휴무 · 제보 (인스타에서 봄) · 2시간 전")
- "제보 엇갈림"이면 인스타 열기 (U15) 를 강조한다
- 영업 상태는 서버가 계산한다

### ⚙️ 백엔드

1. `docs/api-contract-v2.md` 에 제보 저장과 가게 상세의 변경점을 먼저 적고 확인받는다

3. N4 우선순위 + 테스트 (시각 주입 : 제보 직후, 24시간 뒤, 엇갈림, 이벤트 만료)

2. 영업 상태 · 이벤트 표시, 외부 링크

## Execution appetite (제안 — 관리자님 수락 필요)

- Protect : 유효 기간, 엇갈림 처리, 근거 문구
- Cut first : 이벤트 유효 기간을 줄이는 입력 (기본 7일만으로도 R2 충족)
- Stop when : 완료 기준 충족 또는 기획으로 돌아갈 때

## Execution contract

- Goal condition : 휴무를 "인스타에서 봄"으로 제보하면 가게 상세가 "휴무 · 제보 (인스타에서 봄) · 방금"으로 바뀌고, 24시간 뒤 정기 영업시간 기준으로 돌아온다. 같은 날 영업 제보가 하나 더 오면 "제보 엇갈림 — 인스타 확인"이 된다
- Required checks : N4 · N11 테스트, 앱에서 T10 ~ T13 확인, 업데이트가 베타 테스터에게 배포됨
- 바꿔도 되는 곳 : `backend/`, `app/`, `docs/api-contract-v2.md`, `docs/planning/phases/`
- 바꾸지 않을 것 : 기획 문서, 기록 · 태깅 규칙
- 기획으로 돌아갈 때 : 엇갈림 규칙으로 결정되지 않는 경우 (예 : 휴무 제보 2개 + 영업 제보 1개를 다르게 다뤄야 하는가), 이벤트에 구조화된 정보가 필요해진다
