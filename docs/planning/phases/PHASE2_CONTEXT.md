- 별점이 보이는 모든 자리에 메뉴명이 붙는다

## 트랙별 작업

### 🎨 디자인

- 가게 상세, 메뉴 상세, 속성 배지 (해산물 : 포함 / 미포함 / 모름 등, 국물 : 청탕 / 백탕 / 비빔 / 모름), 근거 문구 스타일
- 배지 색은 토큰으로. 아이콘에 이모지를 쓰지 않는다

### ⚙️ 백엔드

1. `docs/api-contract-v2.md` 에 가게 상세 · 메뉴 상세를 먼저 적고 확인받는다 (속성 = 값 · 상태 · 근거 종류 · 근거 문구 · 마지막 확인 · 인원)
2. N2 (시드 단계), N5 (0명), N6, N7 + 테스트

### 📱 프론트

1. 타입 · 호출 함수 · 훅
2. 가게 상세 · 메뉴 상세 화면 (`/shops/[id]`, `/menus/[id]` 형태의 push 라우트), 로딩 · 오류 · 빈 상태

## Execution appetite (제안 — 관리자님 수락 필요)

- Protect : 메뉴 단위 속성 + 근거 표시, 별점 빈 상태, 로딩 · 오류
- Cut first : 메뉴 상세의 장식 요소
- Stop when : 완료 기준 충족 또는 기획으로 돌아갈 때

## Execution contract

- Goal condition : 지도 → 시트 → 가게 상세 → 메뉴 상세로 들어가면, 메뉴마다 종류 · 형태 · 해산물 · 국물과 근거가 보이고 별점 자리에 "아직 평가 없음"이 나온다
- Required checks : 백엔드 테스트, 앱에서 T4 · T5 확인 (같은 가게 두 메뉴의 속성이 다르게 보이는 예 : 라멘야누 쇼유 / 마제소바, 이리에 맑은도미 / 진한도미)
- 바꿔도 되는 곳 : `backend/`, `app/`, `docs/api-contract-v2.md`, `docs/planning/phases/`
- 바꾸지 않을 것 : 기획 문서, 필터 · 기록 · 제보 기능
- 기획으로 돌아갈 때 : 시드 근거를 화면에 어떻게 말할지 정해지지 않은 경우가 생긴다, 메뉴 속성 응답 모양이 Phase 4 상태를 담지 못한다
- Checkpoint : API / 가게 상세 / 메뉴 상세 단위로 PR
