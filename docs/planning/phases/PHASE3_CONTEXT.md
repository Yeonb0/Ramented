## Do not use as build scope

- 형태 · 종류 · 타레 필터 (v2.0 밖. 필터는 해산물 · 국물 칸만)
- "확인된 것만" 토글 (B1에서 고르지 않은 선택지)

## Must preserve

- 요구 : **R0** 국물 속성으로 포함 · 제외할 수 있어야 한다
- **B1** : 해산물 제외는 "미포함 확정" 메뉴만 통과한다. 시드 값 · 모름 · 의견 갈림 · 변경 의심 · 포함은 모두 탈락. 시드에 미포함이 0개이므로 **지금은 해산물 제외를 켜면 0곳**이 정상이다
- **B2** : 국물 칩은 청탕 / 백탕 / 비빔. 여러 개 고르면 OR. 확정 값 또는 시드 값이 고른 칩 중 하나면 통과, 의견 갈림 · 모름은 탈락
- 해산물 제외와 국물 칩을 함께 켜면 AND
- **B3** : 통과 메뉴 ≥ 1 → 가게 마커에 "통과 n개", 0 → 흐린 점선 마커. 필터를 모두 끄면 기본 배지. 가게 상세에서 통과 메뉴를 위로
- 필터 판정은 서버가 한다 (N3). 클라이언트는 결과만 그린다
- 마커는 WebView 안에서 SVG 문자열로 (`buildMarkerSvg`)

- 필터 칩 (켜짐 / 꺼짐), 마커 "통과 n개" 배지와 흐린 점선 마커, 0곳 안내

### ⚙️ 백엔드

3. 가게 상세 조회에 필터 조건을 받아 통과 메뉴 정렬

2. `buildMarkerSvg` 세 모양, 시트의 통과 수, 0곳 안내

## Execution contract

- Goal condition : 청탕 칩을 켜면 청탕 메뉴가 있는 4곳 (라멘롱시즌, 사루카메, 이리에라멘, 소월옥) 만 "통과 n개" 배지로 남고 나머지는 흐려진다. 해산물 제외를 켜면 모든 마커가 흐려지고 0곳 안내가 나온다
- Required checks : N3 판정 테스트 (상태 × 칩 조합), 앱에서 T2 · T3 확인
- 바꿔도 되는 곳 : `backend/`, `app/`, `docs/api-contract-v2.md`, `docs/planning/phases/`
- 바꾸지 않을 것 : 기획 문서, 기록 · 태깅 (Phase 4)
- 기획으로 돌아갈 때 : B1 · B2 · B3로 결정되지 않는 조합이 나온다 (예 : 츠케멘의 국물 칩), 마커 세 모양만으로 표현이 안 되는 경우
