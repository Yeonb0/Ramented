## Current situation

- Trigger or context : 라멘을 먹으러 갈 가게를 고를 때 (S1, S3, S4)
- Current approach : **미확인.** 일반 지도 앱 검색 + 가게 인스타 확인으로 추정 (S2에서 유추, 추론)
- Current result :
  - 해산물 육수 메뉴를 미리 걸러낼 수 없다 (S3)
  - 가게 단위 정보로는 부족하다 — 같은 가게의 시오와 쇼유가 육수가 다를 수 있다 (S7)
  - 청탕인지 백탕인지 알 수 없다 (S3)
  - 정통 가게인지 알 수 없다 (S4)
  - 인스타를 안 쓰는 사람은 휴무 · 이벤트를 모른다 (S2)
- Where it breaks down : 가게에 가서 메뉴를 시켜 보기 전까지 국물 · 정통성 · 영업 여부를 확신할 수 없다. 실제 빈도는 **미확인**
- Who : 라멘을 즐겨 먹는 앱 사용자 일반 (S6). 1차 근거는 관리자님 본인 경험
- Evidence and confidence : 1인 경험 진술. "라멘 지도 앱이 없다" (S1) 는 시장 조사로 확인하지 않음

**Frame equation**

- x : 라멘 가게를 고를 때, 일반 지도에는 메뉴별 국물 속성 · 정통성 평가 · 오늘의 영업 / 이벤트 정보가 없고, 영업 정보는 인스타에 흩어져 있다. 다녀온 경험은 어디에도 쌓이지 않는다
- f() : 미정 (shaping에서 결정)
- y : 사용자가 원하지 않는 국물의 **메뉴**를 빼고, 청탕 / 백탕과 다른 사람들이 매긴 정통성을 보고, 인스타 없이도 휴무 · 이벤트를 알고 고를 수 있다. 다녀온 뒤에는 기록이 쌓이고 등급으로 다른 사람과 견줄 수 있다
- Gap : 이 정보들이 (a) 메뉴 단위로 구조화되어 있지 않거나 (P3), (b) 사람들의 평가로 모여 있지 않거나 (P4), (c) 다른 플랫폼에 흩어져 있다 (P2)

## Operating model (M)

- Authority : Working
- Relevant operating conditions :
  - M1. 메뉴별 국물 속성 · 정통성 정보는 공개 데이터셋에 없다고 가정한다 (가정)
  - M2. 정보는 사용자들이 채운다 — 정통성은 평가로 (S5), 서비스는 다수 사용자 대상 (S6)
  - M3. 사장님들은 휴무 · 이벤트를 인스타에 올리며 (S2), 이를 자동으로 가져올 공식 경로는 없다 (E2, 재확인 필요)
- Causal assumptions :
  - 사용자가 채우는 정보는 참여자가 적으면 비어 있거나 오래된다 (가정)
  - 정보가 부정확하면 (특히 휴무) 지도 자체를 신뢰하지 않게 된다 (가정)
- Revisit conditions : 공개 데이터 소스나 인스타 연동 경로가 확인되면 M1 · M3 재검토

## Problem

- 라멘 가게를 고를 때 결정에 필요한 정보 (메뉴별 국물 속성, 정통성 평가, 오늘 영업 여부 · 이벤트) 를 한 곳에서 볼 수 없다 (S1 ~ S5)
- 국물 속성이 메뉴마다 다른데, 가게 단위로만 정보가 있다 (S7)
- 특정 국물 계열을 **빼고** 보는 것이 불가능하다 (S3)
- 영업 · 이벤트 정보가 인스타 사용자에게만 닿는다 (S2)
- 다녀온 경험이 기록으로 남지 않는다 (S8)

## Outcome

- 사용자가 가기 전에 그 가게의 **어느 메뉴**가 자기 취향에 맞는지 판단할 수 있다
- 원하지 않는 국물의 메뉴 · 가게를 지도에서 치워 버릴 수 있다
- 다른 사람들의 메뉴 별점을 보고 정통 가게를 스스로 알아보고 골라 갈 수 있다 (별도 "정통" 표시는 두지 않음, S10)
- 인스타 없이도 휴무 때문에 헛걸음하지 않는다
- 다녀온 한 그릇이 기록으로 쌓이고, 그 기록이 등급이 되어 경쟁하는 재미가 있다
