# 라멘타쿠 v2.0 — 디자인 방향

> 2026-11-13 Phase 1 세션에서 관리자님과 정한 v2 디자인 방향. 프로젝트 지침의 "v2 디자인 재검토"가 이 문서다.
> 이 문서와 v1 디자인 문서 (README 「디자인 시스템」, `docs/ramentaku_screendesign.md`) 가 충돌하면 이 문서가 이긴다.

## 1. 의도

- **"내가 먹은 한 그릇을 책에 그려서 기록하는 앱"** 처럼 보이게 한다
- 참고한 느낌 : 모바일 게임 "좋은 피자, 위대한 피자"의 손으로 그린 듯한 색감과 버튼. 굵은 진갈색 펜 선, 단색 면, 살짝 삐뚤어진 모서리, 눌리는 느낌의 버튼
- 가져오는 것은 **느낌** 뿐이다. 그 게임의 캐릭터 · 그림 · 레이아웃을 따라 그리지 않는다
- 색은 **라멘 국물 계열로만** 쓴다 (관리자님 2026-11-13). 게임의 코랄 · 분홍은 가져오지 않는다
- 구조는 Meta의 디자인 시스템 Astryx (`github.com/meta/astryx`) 를 참고한다. Astryx는 웹 전용 (React DOM + StyleX) 이라 코드는 쓰지 않고 **토큰 3층 구조와 "규칙을 테스트로 검증한다"는 방식**만 가져온다

## 2. 목표 · 비목표 · 실패 조건

**목표**

- 앱 전체를 "기록장" 톤 (시안 B) 으로 통일한다. 카드와 시트는 노트 한 장, 제목은 리본 띠
- 기록 화면 (P4 방문 기록 작성, P7 내 기록) 은 "책" 느낌으로 한 단계 더 간다
- 색 · 선 두께 · 라운드는 `app/src/theme` 한 곳에서만 정해지고, 국물 색 하나를 바꾸면 앱과 지도 마커가 같이 바뀐다

**비목표**

- 다크 모드 (v1과 같이 v2.0 범위 밖)
- 손글씨 폰트 도입 (나눔스퀘어라운드 유지)
- 지도 화면을 책으로 만드는 것 (시안 C는 기록 화면에만 적용)
- v2.0에서 테마를 여러 개 두는 것 (Astryx식 테마 패키지 · 아이콘 레지스트리는 만들지 않음)

**실패 조건 (동작해도 실패로 본다)**

- 그림자 · 그라디언트 · 이모지 아이콘이 하나라도 들어간다
- 화면 코드나 WebView 스크립트에 헥사값 · 픽셀 상수가 직접 쓰인다
- 손그림 느낌 때문에 글자 · 별점 · 영업 상태 같은 정보가 읽기 어려워진다 (펜 선과 글자는 종이 위에서 대비 기준을 넘어야 한다)
- 리본이나 장식이 44px 터치 영역을 가리거나 줄인다

## 3. 정해진 것 (관리자님 결정)

| 항목 | 결정 |
|---|---|
| 전체 톤 | 시안 B · 기록장 |
| 책 느낌 범위 | P7 내 기록 + P4 방문 기록 작성 (선택지 2). P8 프로필 · 지도 · 가게 상세는 기록장 톤만 |
| 버튼 | ② 아래 테두리만 두껍게 (그림자 아님) |
| 색 | 라멘 국물 계열만. 분홍 점선 · 코랄 리본 없음 |
| 토큰 구조 | Astryx식 3층 (팔레트 → 의미 토큰 → 부품 처리) |

## 4. 검토한 방식 (Approaches)

| 방식 | 내용 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| 1. 값만 교체 | 지금 `colors.ts` 의 헥사값을 바꾸고 토큰 몇 개 추가 | 가장 빠름 | 같은 색이 의미만 다른 이름으로 여러 번 적힘. 국물 색 하나 바꿀 때 여러 곳 수정 |
| **2. 3층 구조 (선택)** | 팔레트 · 의미 토큰 · 부품 처리를 분리 | 헥사값이 한 파일에만 있음. 마커 · 앱이 같은 팔레트를 씀. 부품 모양을 테마에서 한 번에 바꿈 | 처음 옮기는 작업이 1보다 큼 |
| 3. 2 + 테마 패키지화 | 테마별 아이콘 레지스트리, AI용 테마 문서 자동 생성 | 테마를 여러 개 둘 때 유리 | 테마가 하나뿐인 앱에서는 얻는 게 적음 |

선택 이유 : 관리자님이 Astryx에서 참고하려던 것이 이 구조이고, v1에서 이미 "색 정의가 두 벌이 되면 안 된다" (앱 ↔ WebView) 는 문제를 겪었다.

## 5. 시각 언어

### 5.1 색 — 국물 팔레트

팔레트 계열은 국물 이름으로 짓는다. 아래 값은 **시작값**이고, 대비 검사 (§ 7) 를 통과하도록 구현 중 조정할 수 있다.

| 계열 | 쓰임 | 시작값 (밝음 → 어두움) |
|---|---|---|
| `shio` 시오 | 종이 · 배경 | 10 `#FDF8EE` · 20 `#FBF2E2` · 30 `#F4E6CF` · 50 `#E2D2B6` · 70 `#CBB593` |
| `paitan` 파이탄 | 지도 바탕 톤, 채워진 칸, 선택 강조 면 | 20 `#F6E6CF` · 40 `#EFD3AE` · 60 `#E0B88C` |
| `shoyu` 쇼유 | 리본, 주요 버튼, 별, 펜 선, 갈색 바 | 30 `#DDB27A` · 40 `#D9963F` · 50 `#B98B5E` · 60 `#A2764C` · 70 `#7A5334` · 80 `#6A4729` · 90 `#3B2C21` |
| `miso` 미소 | "지금 못 감" 강조 (브레이크 · 휴무) 만 | 50 `#C0654B` · 60 `#B5503F` · 70 `#83381F` |
| `negi` 파 | 채워짐 · 확정 체크, 영업 중 | 50 `#6F8F62` · 70 `#4E6B43` |

- `shoyu.80` 은 펜 선과 갈색 바가 같이 쓴다. 보내주신 게임 화면의 펜 선 색과 v1의 바 색이 거의 같아서 하나로 합쳤다
- `shoyu.40` (앰버) 은 별 색이다 (v1 `star`)
- v1의 마커 색 (타레 × 청탁 6색) 은 v2.0에서 쓰지 않는다. breadboard가 마커를 "기본 / 통과 n개 / 흐림" 세 모양으로만 그리기 때문이다 (breadboard Open questions 1). 나중에 타레 색이 필요해지면 이 팔레트의 계열에서 다시 고른다

### 5.2 선

- 펜 선 = `shoyu.80`. 카드 · 시트 · 버튼 · 리본 · 마커의 바깥 선은 모두 이 색이다
- 두께 : 바깥 선 2.5, 안쪽 요소 (칩 · 칸) 2, 구분선 1 (v1의 1.5보다 굵게. 게임처럼 "펜으로 그은" 느낌을 내는 핵심)
- 구분선은 **실선**, 색은 `shio.50`. 분홍 점선은 쓰지 않는다
- 점선은 **"아직 비어 있는 칸"** (§ 5.5) 한 곳에만 쓴다. 색은 `slotEmpty` (`shoyu.60`)

### 5.3 모서리 — 삐뚤어진 라운드

- RN `View` 는 타원 반경 (`a / b`) 을 지원하지 않으므로, **네 모서리 반경을 조금씩 다르게** 줘서 손으로 그린 느낌을 낸다
- 예 : 노트 카드 `[16, 20, 15, 19]` (좌상 · 우상 · 우하 · 좌하)
- 이 네 값 묶음은 `layout.ts` 의 `wobble` 토큰으로만 쓰고, 화면에서 숫자를 쓰지 않는다
- 갈색 바 (헤더 · 탭바) 에는 여전히 라운드를 주지 않는다 (v1 규칙 유지)
- 실제로 흔들리는 선은 SVG로 그리는 것 (마커 · 리본 · 아이콘 · 일러스트) 에서만 쓴다

### 5.4 깊이 · 버튼

- 그림자 금지는 유지한다. 깊이는 면 + 펜 선으로만 낸다
- **버튼 ②** : 테두리 2.5, **아래 테두리만 5**. 같은 펜 선 색이라 그림자가 아니라 "두꺼운 선"이다
  - 눌렀을 때 : 아래 테두리 2.5로 줄이고 그만큼 (2.5) 아래로 내려서, 버튼이 눌려 들어가는 느낌을 낸다
  - 주요 버튼 : `primary` (`shoyu.70`) 면 + `onPrimary` 글자. 보조 버튼 : `paper` 면 + `text` 글자
- 이 "아래 테두리 두께"는 `check:tokens` 의 그림자 규칙에 걸리지 않는다 (`borderBottomWidth` 는 그림자 속성이 아님). 문서상 허용되는 유일한 두께 장치로 명시한다

### 5.5 기록장 부품

| 부품 | 모양 | 쓰는 곳 |
|---|---|---|
| 노트 카드 | `shio.10` 면, 펜 선 2.5, `wobble` 모서리 | 모든 카드 |
| 노트 시트 | 노트 카드와 같은 면 · 선, 위쪽 두 모서리만 `wobble`, 아래는 화면 끝에 붙음 | 미리보기 시트 (P1.2) 등 |
| 리본 | SVG. 양 끝이 V자로 파인 띠, `ribbon` 면 + 펜 선 2 + `onRibbon` 글자. 카드 위 가장자리에 반쯤 걸쳐 놓인다 | 카드 · 시트 · 책 쪽의 제목 |
| 칸 (PageSlot) | 비어 있음 : 지름 = 터치 타겟 이상, `slotEmpty` 점선 2 / 채워짐 : `fillSoft` 면 + 펜 선 2 + `success` 체크 | P4 별점 · 사진 자리, P7 쪽 |
| 쪽 넘김 | 화살표 버튼 2개 (버튼 ② 모양) + 점 (현재 `primary` 채움, 나머지 `slotEmpty` 테두리) + `3 / 12` 숫자 | P7 |

### 5.6 책 화면 (P4 · P7) — 방향만, 시안 · 구현은 Phase 4

- **P7 내 기록** : 한 그릇 = 한 쪽. 폰이 세로라 펼친 두 쪽이 아니라 **한 쪽씩** 보여주고 쪽을 넘긴다. 쪽 위에 메뉴명 리본, 아래로 가게명 · 별점 (+ 메뉴명 규칙) · 방문일 · 코멘트
- **P4 방문 기록 작성** : "책의 빈 쪽에 쓰는" 느낌. 키보드가 올라오는 전체 화면 폼이라 **책 테두리 · 책갈피는 쓰지 않고** 종이 · 리본 · 칸만 쓴다. 별점 · 사진 자리를 빈 칸으로 두고, 채우면 체크가 붙는다
- 지도 · 가게 상세 · 메뉴 상세 · 프로필은 기록장 톤 (노트 카드 · 리본) 까지만

```
┌─ 내 기록 ─────────────┐
│ ▕▔▔ 토리파이탄 쇼유 ▔▔▏│ ← 리본 (메뉴명)
│  멘야 산다이메         │
│  ★★★★☆  이 메뉴의 별점 │
│  11.08 방문            │
│  ────────────────────  │ ← 실선 구분
│  국물이 진했다…        │
│                        │
│   ◀   ● ○ ○ ○   ▶     │  3 / 12
└────────────────────────┘
```

### 5.7 타이포 · 갈색 바

- 나눔스퀘어라운드 R / B / EB 유지. 게임 화면의 한글도 둥근 고딕 계열이라 손글씨 폰트 없이 톤이 맞는다
- 헤더 · 탭바의 갈색 바 (`shoyu.80`) 와 바 위 반전 팔레트 (`onBar`) 는 유지한다

## 6. 토큰 구조 (3층)

```
app/src/theme/
  palette.ts      1층  국물 계열별 단계 색. 헥사값이 있는 유일한 파일
  colors.ts       2층  의미 토큰 (paper, ink, text…) → palette 참조. onBar 포함
  components.ts   3층  부품 처리 (noteCard, noteSheet, button, ribbon, pageSlot, pager)
  marker.ts       2 · 3층  지도 마커 토큰 → palette 참조
  layout.ts       간격 · 라운드 · wobble · 선 두께 · 터치 타겟
  typography.ts   (변경 없음)
  index.ts        단일 진입점
```

**2층 의미 토큰 (최소 목록)**

| 토큰 | 가리키는 값 |
|---|---|
| `paper` / `paperRaised` / `paperSunken` | `shio.10` / `shio.20` / `shio.30` |
| `ink` (펜 선) | `shoyu.80` |
| `divider` | `shio.50` |
| `slotEmpty` | `shoyu.60` |
| `text` / `textSecondary` / `textMuted` | `shoyu.90` / `shoyu.80` / `shoyu.70` |
| `primary` / `primaryPressed` / `onPrimary` | `shoyu.70` / `shoyu.80` / `shio.10` |
| `ribbon` / `onRibbon` | `shoyu.70` / `shio.10` |
| `fillSoft` (채워진 칸 · 선택 면) | `paitan.40` |
| `star` | `shoyu.40` (항상 `ink` 외곽선과 함께 그린다) |
| `success` (영업 중 · 확정, 글자에도 씀) | `negi.70` |
| `danger` (브레이크 · 휴무) | `miso.60` |
| `bar` | `shoyu.80` |

시작값 대비 계산 결과 (2026-11-13, `paper` = `shio.10` 기준) : `text` 12.65 · `textSecondary` 7.79 · `textMuted` 6.37 · `ink` 7.79 · `slotEmpty` 3.79 · `success` 5.65 · `danger` 4.74 · `onPrimary` / `primary` 6.37 · `onBar.text` / `bar` 7.92. 처음 잡았던 `shoyu.60` 주요 버튼 (3.79), `shio.70` 점선 (1.88), `negi.50` 글자 (3.43) 는 기준 미달이라 위처럼 한 단계씩 진하게 바꿨다. `star` 면 (2.37) 은 기준 미달이지만 별은 항상 `ink` 외곽선으로 그리므로 외곽선이 대비를 맡는다.

**3층 부품 처리** — 부품 컴포넌트는 `components.ts` 의 값만 읽는다. 예 :

```ts
export const button = {
  borderWidth: borderWidth.outline,          // 2.5
  borderBottomWidth: borderWidth.buttonBase, // 5
  borderColor: colors.ink,
  pressed: { borderBottomWidth: borderWidth.outline, translateY: 2.5 },
  radius: wobble.button,
  variant: {
    primary: { backgroundColor: colors.primary, color: colors.onPrimary },
    secondary: { backgroundColor: colors.paper, color: colors.text },
  },
} as const;
```

**지도 스켈레톤** : v1 `mapSkeleton` (타일을 받기 전 바탕색) 은 유지하되 값을 팔레트 참조로 바꾼다 (바탕 `paitan.20`, 길 `shio.10`).

**WebView** : 마커 SVG는 v1 방침대로 `buildMarkerSvg` 가 `marker.ts` 만 읽어 문자열을 만들고 주입한다. WebView 쪽에 색을 직접 쓰지 않는다.

## 7. 규칙을 검사로 박기 (Astryx의 "tested conventions")

`app/scripts/check-tokens.mjs` (Node, Windows에서도 실행) 를 넓힌다.

1. 헥사값 허용 범위를 `src/theme/` 전체 → **`src/theme/palette.ts` 한 파일**로 좁힌다
2. 그림자 (`shadow*` · `elevation`) 금지 — 기존 유지
3. **대비 검사** 추가 : 정해둔 쌍이 기준을 넘는지 계산한다
   - 본문 글자 (`text`, `textSecondary`) / `paper` : 4.5 : 1 이상
   - `onPrimary` / `primary`, `onRibbon` / `ribbon`, `onBar.text` / `bar` : 4.5 : 1 이상
   - 펜 선 (`ink`) · `slotEmpty` / `paper` : 3 : 1 이상 (선 · 아이콘 기준)
4. 대비 검사 (3번) 는 이 스크립트가 아니라 jest 테스트 `app/src/theme/__tests__/contrast.test.ts` 에 둔다. `palette.ts` 가 TS 파일이라 `.mjs` 스크립트에서 바로 읽을 수 없기 때문이다 (Phase 1 구현 중 변경, `jest-expo` 도입)

## 8. Phase 1에서 만드는 범위

| 만든다 | 만들지 않는다 (다음 Phase) |
|---|---|
| 팔레트 · 의미 토큰 · `wobble` · 선 두께 토큰 전체 | 책 화면 시안 · 구현 (Phase 4) |
| `check-tokens.mjs` 확장 (§ 7) | 칸 · 쪽 넘김 부품 (Phase 4) |
| 부품 : 노트 카드, 노트 시트, 리본, 버튼 ② | 필터 칩 (Phase 3) |
| 기본 마커 SVG (아래) + 선택된 마커 | "통과 n개" · 흐림 마커 (Phase 3) — 토큰 자리만 |
| 미리보기 시트 (가게 이름 리본 + 영업 상태 문구) | 아이콘 세트 다시 그리기 (필요해지는 Phase에서) |
| 로딩 · 실패 + 다시 시도 상태 (버튼 ②) | |

**기본 마커 (U2, 필터 꺼짐)** : `paper` 면 + 펜 선 2.5의 원 안에 작은 그릇 모양을 펜 선으로 그린다. 숫자 없음 (v2 지도 API에는 메뉴 수가 없다).
**선택된 마커** : 한 단계 크게, 면을 `fillSoft` 로.

**미리보기 시트 문구 색** : 서버가 내려준 영업 상태 enum을 색 토큰에 1 : 1로 잇는다 (영업 중 → `success`, 브레이크 · 영업 종료 · 정기 휴무 → `danger`, 모름 → `textMuted`). 문구 자체는 서버가 준 근거 문구를 그대로 쓴다. 표시용 매핑일 뿐 영업 여부를 클라에서 계산하지 않는다.
